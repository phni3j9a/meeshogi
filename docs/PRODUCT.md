# 製品仕様

**meeshogi**はミーアキャットをマスコットにしたiOS・Android向け棋譜解析・戦績管理アプリ。無料で棋譜を取り込み、検討し、記録を蓄積する体験を土台とする。

現在は端末内SekireiとCloud Free／Precisionが共存する。今後はCloudへ一本化する方針で、Sekirei撤去後の解析仕様（サーバー詰み判定・オフライン・利用条件）は [Issue #45](https://github.com/phni3j9a/meeshogi/issues/45) で実装中、Sekirei撤去は [Issue #24](https://github.com/phni3j9a/meeshogi/issues/24) の後続作業。以下は現在維持する仕様であり、将来機能を追加の完了条件にしない。

## 棋譜と保存

- 将棋ウォーズ・棋桜のKIFを、ユーザー操作によるクリップボード貼り付け／OSのファイル選択で取り込む。サービスへのログイン・スクレイピングはしない。
- 日時、対局者名・段級、時間設定、指し手・消費時間、終局理由・結果と元テキストを保持する。不正な棋譜を部分的に成功扱いして保存・集計しない。
- サービスごとに複数の対局者名を登録できる。名前・先後・勝敗を推定し、曖昧なら確認する。棋桜のサービス名をKIFヘッダーだけで断定しない。登録名の変更時は既存対局の帰属も確認・修正できる。
- 自分を含まない棋譜も保存・解析できるが自分の戦績に含めない。サンプルの名前や評価値をアプリの初期値にしない。
- 同一局の二重保存・二重集計を防ぐ。日時の表記差を正規化し、対局者・初期局面・全手・原本結果・終局理由で比較する。衝突が疑われる場合はユーザーが選択する。
- 本譜・解析結果・設定は端末に保存し、再起動後も開ける。対局結果の手動修正は原本と分け、原本へ戻せる。KIF共有は元テキストのUTF-8 `.kifu`で、手動修正と書き出す原本の違いを表示する。
- 保存後の自動全局解析は既定オン。設定／取り込み時にオフにでき、保存後に手動開始できる。ログイン・同期・課金は現在の利用条件にしない。

## 解析・検討

- 解析中も盤面操作・手送り・閲覧ができ、進捗・候補手・読み筋を順次表示する。グラフから局面へ移動でき、停止・再開の手段を持つ。
- 評価値とグラフは先手視点（正は先手有利、負は後手有利）。盤面反転で符号を変えない。通常探索のmateは符号付きの`+M5`／`-M5`として表示し、グラフでは±1500の端へ置く。
- 合法手ゼロかつ王手中は「詰み終局」。先手番なら-1500、後手番なら+1500。王手なしの合法手ゼロは区別して欠測にする。mate=0・投了・時間切れ・手動結果から詰みバッジを生成しない。
- 未解析・初回反復未完了の`incomplete`・中断は欠測とし、ゼロで補完しない。完了済み反復の`complete`は`budgetReached=true`でも有効。
- 端末内の全局解析では、検証済みの初回反復の予算不足だけを一度スキップして後続へ進む。不正結果・native障害・保存失敗・キャンセルでは停止する。不完全な結果は保存せず、予算を自動増加しない。
- 有効な結果が全局面に揃った場合だけ「全局解析が完了しました」と表示する。不足があれば「解析処理が終了しました」とし、解析済み・探索量不足を分ける。設定変更で明示的に再試行できる。再起動後に保存していない不足理由を推定しない。
- 保存結果はエンジン・モデル・局面・探索条件が一致するものだけを現在の評価、候補、グラフ、詰み、完了件数に使う。古い結果を新しい結果に見せかけない。
- 任意局面から合法手で分岐し、戻って別の手を試せる。「本譜に戻る」で分岐元へ戻る。分岐を永続保存せず、本譜・全局グラフ・戦績を上書きしない。分岐局面は解析せず、評価値・候補手・詰みバッジを表示しない。局面単位の追加解析（深掘り）は提供しない。

## 解析方式の選択

設定で「端末内（Sekirei）」「Cloud・無料」「Cloud・精密」を選ぶ。既定はSekirei。全局解析は選択中の方式を使い、結果は方式ごとに分離して保存・表示する。

- Cloudは開発用stagingで、production serviceではない。接続先はビルド時に指定する。匿名認証で両方式を利用できる。Cloud・無料は1 ownerあたり1日10局（Asia/Tokyo）までとし、ログインは導入しない。再インストールで匿名credentialを取り直せば超えられるが、許容する。Precision個別許可は開発中は無効化している。同時active 1局、512手上限、探索条件は維持する。
- 512手を超える棋譜はCloudを開始せず「Cloud解析は512手までの棋譜に対応しています」と案内する。棋譜の保存・閲覧・戦績は従来どおり使える。
- Cloud結果の合法PV・合法手数に応じた候補数・終局判定はサーバーが確定する。端末は形式・局面・identity・profile・評価値・実効候補数を確認し、全合法手生成・全PV再生を繰り返さない。盤面で実際に指す手の合法性は確認する。
- Cloud jobはアプリ終了・背景移行・通信断でもサーバーで継続し、同じidempotency key／jobIdへ再接続する。明示取消をサーバーが確定するまで取消済みと表示しない。
- active／送信結果未確認のjobに対応する棋譜は、サーバーの終了／取消を確認するまで保持する。ownerのcredential喪失・認証拒否で再接続不能と識別できた場合に限り、jobが継続し得ること・復帰を放棄することを説明して、明示確認後に端末内データを削除できる。一時障害・一般エラー・単なるpoll停止は例外にしない。
- Cloudの通常mateから1手／3手詰めバッジを作らない。Cloudのバッジは、サーバーが結果の保存時に証明した1手／3手詰め（`mateProof`）だけから作る。証明の予算切れは「詰みなし」にしない。開発用の方式比較exportは [ANALYSIS-COMPARISON.md](ANALYSIS-COMPARISON.md) を参照する。

## 詰み・戦績・戦型

- 1手／3手詰めバッジは、現在の手番側が連続王手で全合法応手に対して詰ませられると証明した場合だけ表示する。1手があれば1手、1手で詰まず3手以内なら3手。高い評価値・一本の読み筋・LLMの推測は根拠にしない。
- 答えはタップまで隠し、代表手順を盤上で再生する。唯一解と断定せず、閉じると元の局面へ戻る。未解析・中断・予算切れを「詰みなし」の証明にせず、3手で未発見でも長手数の詰みを否定しない。
- 通算・月別・先後・サービス別の戦績を持つ。勝率は勝ち／（勝ち＋負け）で、引き分け・中断・結果不明を区別し、分母ゼロは未定義表示。
- 代表戦法と相居飛車・対抗形・相振り飛車を分類する。序盤の配置・進行に基づき、終局の飛車位置だけで判定しない。未分類を許容し、手動修正を自動分類で上書きしない。
- 自分／相手を分けて戦法別の勝率・先後別・該当対局を表示する。主分類と転換時の規則は [OPENINGS.md](OPENINGS.md) を参照し、同じ対局を重複集計しない。

## 画面と対象外

基本タブは「棋譜」「戦績」「設定」で、起動時は棋譜一覧。検討などの詳細画面は戻る、取り込み・詰み手順は閉じる操作を用意する。盤面は自分側が手前で始め、画面サイズに合わせる。[デザイン基準](design/README.md) と [解析画面](design/analysis-refresh.md) を参照する。

駒セットは黄楊・白木・桜木・青磁。既定は黄楊で、先後の見本を比較して選び、保存後に盤上・持駒・詰み手順へ共通反映する。保存失敗では旧選択を保ってエラー表示する。生成素材の地色は同じセット・同じ側で共通にし、現在の持ち主に従う。盤面反転で先後の色を変えない。素材・字形は [駒セット](design/piece-sets.md) を参照する。

LLM解説・助言、課金、ログイン・クラウド同期、全件バックアップ、分岐の永続保存、詰めろ・必至・5手以上のバッジ、囲い・戦法の網羅、対局サーバー・オンライン対戦、PC専用版は現在の必須範囲に含めない。
