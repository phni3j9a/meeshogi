# 戦型分類ルール

棋譜の自動分類は `src/domain/index.ts` の `OPENING_RULE_VERSION`（現在は `v1`）で管理する。初期版では序盤の配置から確実に判定できる代表分類だけを返し、手数や評価値から戦法名を推測しない。判定できない棋譜は `unknown` として保存し、利用者が設定した手動分類を表示・集計では優先する。

## 自分側の分類

本譜の先頭３２手以内にある、その側の元飛車による横移動だけを調べる。飛車は未成・非打ち・非捕獲で、移動元と移動先が自陣三段（先手は７〜９段、後手は１〜３段）にある場合だけ候補にする。先手は２筋、後手は８筋を初期筋とし、初期筋内の縦移動（例: ２八飛から２六飛）は分類の根拠にしない。

| 分類 | 先手の飛車 | 後手の飛車 |
| --- | ---: | ---: |
| 四間飛車 | ６筋 | ４筋 |
| 中飛車 | ５筋 | ５筋 |
| 三間飛車 | ７筋 | ３筋 |
| 向かい飛車 | ８筋 | ２筋 |

対応表にない筋へ最初に飛車を動かした場合は `unknown` とし、その後の転換で上書きしない。候補がなく元飛車が３２手以内に初期筋に留まり、棋譜が少なくとも２０手ある場合だけ居飛車（`static`）とする。２０手未満、元飛車の消失、３２手を過ぎてからの移動は `unknown` とする。この分類は序盤配置と進行から確実に読める情報だけを使う。

成った飛車（龍）の移動は分類の根拠にしない。振り飛車への移動後に成った場合も、最初の未成飛車の移動で分類済みになる。初期局面が平手でない棋譜はドメイン層で取り込まないため、分類対象は平手の本譜に限る。

## 対局の分類と手動上書き

`ParsedGame.openings.black` と `.white` は、自動分類値と `manual` 値を保持する。画面や戦績集計で使う実効値は `manual ?? automatic` とする。手動値を削除すると、保存された自動分類へ戻る。自動分類のルールを変更する場合は `OPENING_RULE_VERSION` を更新し、既存棋譜の自動値を再計算できるようにする。

`openingSide` を指定しない集計では自分側の分類を使う。相手側の分類を集計する場合は `openingSide: 'opponent'` を指定する。自分の側が未確定の棋譜は戦績集計から除外し、未分類（`unknown`）の戦型と勝敗不明を混同しない。
